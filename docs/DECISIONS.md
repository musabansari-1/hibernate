# Decisions

1. **Keep TypeScript in charge of semantic behavior.** Rust implements the Windows and durability boundary. No additional service framework or cloud dependency is needed.
2. **Persist before close, then append resource/result observations.** Losing a post-close-only snapshot would violate the primary safety requirement, including the reordered lifecycle in later product notes.
3. **deep sleep and Quick Sleep remain separate.** This preview implements no suspension or memory trimming. Suspended processes retain state and do not establish reboot-safe reconstruction.
4. **Use Chrome's extension API instead of private profile files or CDP in the product.** It exposes tabs/groups/windows inside the correct installed profile without reading cookies or browser databases. CDP is used only by isolated automated tests. [Chrome tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs), [windows](https://developer.chrome.com/docs/extensions/reference/api/windows).
5. **Create lightweight placeholders for background tabs.** The tabs API has no create-as-discarded flag. Loading destinations and discarding afterward would already incur network and memory work. Placeholder activation restores the original URL. [Tabs create/discard](https://developer.chrome.com/docs/extensions/reference/api/tabs).
6. **Restrict initial automatic close to owned test pages.** The absence of a dirty flag or unload dialog does not prove an arbitrary website has no unsaved application state. No broad “safe” claim is made for ordinary pages.
7. **Use native messaging, not an HTTP control port.** Browser installation explicitly authorizes one extension; there is no web-accessible close endpoint. Windows uses a user-level host registration. [Native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).
8. **Reuse VS Code's own state where possible.** Its workspace persistence and hot exit are useful but have close-path/settings limitations. The extension adds semantic evidence and dirty-state reporting without accessing source buffers. [Workspaces](https://code.visualstudio.com/docs/editing/workspaces/workspaces), [hot exit](https://code.visualstudio.com/docs/editing/codebasics), [extension API](https://code.visualstudio.com/api/references/vscode-api).
9. **Use supported Shell folder observations; do not guess Explorer tabs or terminal cwd.** Shell automation is supported, but its results do not prove complete Windows 11 tab coverage. Terminal reconstruction starts from explicitly supplied context. [Explorer APIs](https://learn.microsoft.com/en-us/windows/win32/shell/developing-with-windows-explorer), [Terminal CLI](https://learn.microsoft.com/en-us/windows/terminal/command-line-arguments), [VS Code shell integration](https://code.visualstudio.com/docs/terminal/shell-integration).
10. **Measure several distinct facts.** System physical memory, Chrome working sets and private commit are not interchangeable. Source-browser ancestry improves attribution without claiming per-tab accuracy. [Windows PSAPI](https://learn.microsoft.com/en-us/windows/win32/api/_psapi/).
11. **Always specify the destination when recreating tab groups.** A real 50-tab regression test found that omitting `createProperties.windowId` moved grouped tabs into the current window rather than the unfocused restore window. Post-restore verification caught the loss.
12. **Sandbox validation pages.** They need no extension privileges. The initial privileged-extension-page workload retained memory in a shared extension rendering context after close, so it did not establish resource reclamation. Sandboxed pages provide an independent experiment; measurements, not assumptions about renderer lifetime, decide whether the proof passes. [Sandboxed extension pages](https://developer.chrome.com/docs/extensions/reference/manifest/sandbox).
13. **No full process hibernation label yet.** A durable project and capability-level verification evidence are central. A collection of launched applications is insufficient. Exact project matches and weak browser suggestions remain visibly distinct.
14. **Review is single-use, state-bound and expiring.** Ordinary Chrome windows require explicit saved-work review followed by fresh semantic checks. Native unload prompts stay under user control. API acknowledgement is not accepted as window-disappearance evidence.
15. **Make project reconstruction durable.** Checkpoints bind app snapshots, Git evidence and service expectations. Each selected part journals intent before execution; restart exposes uncertainty rather than replaying side effects. Finishing the sequence does not manufacture project readiness.
16. **Protect semantic payloads with current-account DPAPI.** Backups use the same account boundary and never import approval or queued actions. This deliberately does not claim full-database encryption, cross-account portability or secure erasure of old copies.
17. **Observe instrumented shell context explicitly.** New Windows Terminal shells report cwd at prompts through a bound native-host session, using no-profile PowerShell. External running shells and command history are never guessed or terminated.
