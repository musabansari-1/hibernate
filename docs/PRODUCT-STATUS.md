# Product status — 14 September 2026

15 September terminal ownership review: automatic Windows Terminal closure is **rejected for the current integration**. Shell identity does not prove exclusive tab/window ownership or safe idleness. Context restoration now requires the exact launch session, normalized saved cwd and live PID/creation identity; the disposable multi-cwd Context Restore regression passes. See [TERMINAL-OWNERSHIP.md](TERMINAL-OWNERSHIP.md) for the ownership decision and the stronger contract required before automatic Terminal close can be reconsidered.

ContextSleep is a working Windows private beta. **The entire specification is not complete.** The existing Tauri / React / Rust / SQLite / extension architecture has been retained, and unsupported or ambiguous lifecycle cases continue to fail closed rather than being presented as complete.

No adapter claims **full process hibernation**. Processing completion is separate from project readiness: a checkpoint reports `ready` only when every restorable capability recorded in that checkpoint supplies the required observed verification evidence; skipped, failed or unverified parts keep it `incomplete`.

## Remaining V1 critical path

1. Run the already-passing packaged developer-project scenario across an **actual Windows reboot** and verify the durable checkpoint can reconstruct the explicitly approved capabilities without replaying interrupted work.

The packaged V1 lifecycle is now proven across a ContextSleep process restart: one checkpoint preflighted and closed VS Code, Chrome and an approved development service; after restarting ContextSleep, restore cold-launched the enrolled Chrome profile and saved VS Code workspace, restarted the explicitly approved service, verified all three capabilities, and reported overall readiness as `ready`. Evidence: `.validation/packaged-v1/results.json`. Shared-process generalization, additional app adapters, broader UI polish and architectural cleanup are outside this V1 critical path.
